# VestaHome — API дополнений, версия 2

> Версия 2 (2026-11-16): поле ввода текста `type=text` (5.1), пароль — `secret=1`. Дополнение, написанное
> для версии 1, работает без изменений; поле `type=text` у VestaHome с `api=1` показывается как значение.

> Сделано (2026-10-26): всё, кроме `volume` (громкость у ГУ меняет только крутилка через MCU — способа из программы
> пока нет). Пример — `VestaCore/plugins/sample` (виджет, экраны, кнопка в панели, своё окно, подписка gps/night),
> живая карта — OSMapsCE. Размер `2x2` (`big`) — только у картинки. Кнопки дополнений в панели — без разрешения
> пользователя (пока); с ними активный раздел панели — без подписи (места узкие).

Примеры: `VestaCore/plugins/sample` (весь API) и `VestaAuto` (отдельный закрытый репозиторий: Android Auto, своё окно с видео). Связь с VestaHome в обоих — VestaCore `vhap.h`: `VhapAddon` + `VhapHello` / `VhapAddonMsg` (найти VestaHome и поздороваться, команды в обработчик, снова `hello` после перезапуска VestaHome, `bye` при закрытии), `VhapSend`, `VhapField`.

Дополнение — отдельная программа Windows CE (свой `.exe`), которая подключается к работающему VestaHome и
добавляет в него виджеты, экраны и кнопки. VestaHome остаётся полностью бесплатным; всё, что делает дополнение,
живёт в его собственной программе. Падение дополнения не роняет VestaHome.

## 1. Где лежит и как запускается

- Папка дополнения: `VHContent\VHPlugins\<Имя>\<Имя>.exe` на `\ResidentFlash` или `\SDMemory`; при одном имени запускается первое. Дополнение на карте запускается и тогда, когда карта появилась позже VestaHome (рядом — его файлы, настройки, журнал).
- VestaHome при старте запускает каждое включённое дополнение. Включить/выключить, посмотреть состояние —
  «Настройки → Дополнения». Выключенное не запускается.
- Дополнение можно запустить и вручную: оно найдёт VestaHome само.
- VestaHome закрывается — шлёт всем `quit`; дополнение должно закрыться само.

## 2. Связь

- Сообщение окна `WM_COPYDATA`. `COPYDATASTRUCT.dwData = 0x56484150` («VHAP»), `lpData` — одна команда
  текстом UTF-16, `cbData` — её длина в байтах (без завершающего нуля).
- Окно VestaHome — класс `VestaHome_Wnd` (`FindWindow`). Дополнение создаёт своё (можно невидимое) окно и
  сообщает его в `hello`; ответы и события VestaHome шлёт туда.
- Команда: `глагол` и поля через табуляцию: `глагол<TAB>ключ=значение<TAB>ключ=значение…`. Значения — любой
  текст без табуляции и перевода строки (их дополнение заменяет пробелом). Неизвестные поля и команды
  игнорируются — так новые версии не ломают старые.
- Одна команда — одно сообщение; `SendMessage` синхронный, отвечать из обработчика долгой работой нельзя
  (не дольше ~100 мс), иначе ждёт другая сторона.

## 3. Знакомство

```
→ hello     id=smarthome  name=Умный дом  ver=1.0  api=1  hwnd=001A0B2C
← welcome   api=2  vh=1.0.261116  night=0  accent=72C059  lang=ru  support=0  unit=VH-EQFK3-005Z8
```
`support` — уровень ключа поддержки этой ГУ (`VestaLicense.key` в папке VestaHome, VestaCore `vlicense`): `0` — нет,
`1` — подписчик, `2` — Соавтор; `unit` — ID ГУ, по которому автор делает ключ. VestaHome без ключа ничего не закрывает;
дополнение решает само: Android Auto показывает заставку поддержки, «Умный дом» работает только у Соавтора. Платному
дополнению не стоит верить `support` — VestaHome открытая, проверяйте ключ сами (`LicenseUnitLevel`).
`id` — латиница/цифры, уникален и **совпадает с именем папки** в `VHPlugins` (по нему VestaHome узнаёт запущенное
им дополнение и хранит его настройки: выключено — файл `disabled` в папке).
Если `api` выше, чем знает VestaHome, — `welcome` с его `api`, дополнение решает само, работать ли.
`← bye` / `→ bye` — отключение.

## 4. Виджет на главной

```
→ widget      id=temp  title=Дом  icon=home  size=1        (1 — малый, 2 — двойной, big — большой)
→ widget.set  id=temp  value=21  unit=°  text=В гостиной  text2=обновлено 12:40  state=ok   (ok|warn|alert)
← widget.tap  id=temp                                          (касание виджета)
```
Поля — те же, что у своих виджетов из ini (`VestaWidgets\*.ini`). Виджет появляется в «Общие → Виджеты
главной», его можно двигать и скрывать, как остальные. Касание без своего экрана — только событие;
с `screen=<id>` — открывает экран дополнения.

### 4.1. Виджет-картинка (живая карта и т. п.)
```
→ widget       id=map  title=Карта  icon=map  size=2x2  image=1      (2x1 — 508×158, 2x2 — 508×328 px на ГУ)
← widget.size  id=map  w=508  h=298  shm=VHAP_smarthome_map          (поле картинки под заголовком, имя памяти)
→ widget.frame id=map                                                 (кадр готов)
← widget.show  id=map  value=1                                        (виджет на экране / 0 — скрыт: не рисовать)
```
Картинка — в общей памяти `CreateFileMapping(…, имя из widget.size)`, которую создаёт VestaHome: заголовок
16 байт (`'VHIM'`, ширина, высота, номер кадра) и пиксели RGB565 построчно сверху вниз. Дополнение рисует кадр,
увеличивает номер и шлёт `widget.frame`; VestaHome перерисовывает только этот виджет. Не чаще 2 кадров в секунду
и только пока `widget.show value=1` — экономия процессора и памяти ГУ.

## 5. Экраны

### 5.1. Описанием (рисует VestaHome, в его стиле: тема, акцент, ночь, «назад»)
```
→ screen      id=main  title=Умный дом  icon=home  nav=1      (nav=1 — просит кнопку в нижней панели)
→ item        screen=main  id=gate   type=button  label=Открыть ворота
→ item        screen=main  id=light  type=toggle  label=Свет у дома  sub=крыльцо  value=1
→ item        screen=main  id=temp   type=value   label=Температура  value=21 °
→ item        screen=main  id=mode   type=seg     label=Режим  options=Эко|Комфорт|Выкл  value=1
→ item        screen=main  id=target type=stepper label=Цель  value=22 °
→ item        screen=main  id=room   type=row     label=Комнаты  sub=4 устройства  link=rooms
→ item        screen=conn  id=host   type=text    label=Сервер  value=mqtt.example        (api 2)
→ item        screen=conn  id=pass   type=text    label=Пароль  secret=1  value=1          (api 2)
→ item.set    screen=main  id=temp   value=22 °           (меняет только названные поля)
→ screen.clear id=main                                     (убрать все элементы, описать заново)
```
Элементы идут сверху вниз в порядке объявления, строками по 56 px; больше, чем влезает, — страницы
(точки, свайп). `type=row` с `link=` открывает другой экран дополнения.
`type=text` (api 2): нажатие открывает клавиатуру VestaHome с текстом `value` (до 63 символов); «Готово» шлёт
`event act=text` с набранным, «Отмена» — ничего. `secret=1` — пароль: строка показывает только «задан» (точки) или
«не задан» по тому, пусто ли `value` (дополнение шлёт туда `1`, а не сам пароль), клавиатура начинает с пустого,
набранное — точками, курсор только в конце, без копирования; пробелы по краям не срезаются. Хранить пароль —
забота дополнения (VestaCore `vsecret`: ключом этой ГУ, как VestaSmartHome).

События:
```
← screen.open   id=main                       (экран открыт — пора обновить значения)
← screen.close  id=main
← event  screen=main  id=gate   act=tap
← event  screen=main  id=light  act=toggle  value=0
← event  screen=main  id=mode   act=seg     value=2
← event  screen=main  id=target act=step    value=+1      (или -1)
← event  screen=conn  id=host   act=text    value=mqtt.example   (api 2; «Готово» на клавиатуре)
```

### 5.2. Своим окном (видео, карта, всё, что рисует само)
```
→ screen  id=phone  title=Экран телефона  icon=phone  nav=1  own=1
→ window  screen=phone  hwnd=001A0C00
```
При открытии такого экрана VestaHome показывает окно дополнения поверх себя на весь экран (0,0–800×480)
и шлёт `screen.open`. Назад — дополнение шлёт `→ back` (своя кнопка или жест), VestaHome шлёт `screen.close`
и поднимается сам. Нижнюю панель окно рисует само, если она ему нужна.

## 6. Где появляется дополнение

- **«Настройки → Дополнения»** — всегда: имя, версия, «подключено / не запущено», включить при старте,
  кнопка в нижней панели (если экран просил `nav=1`), «Открыть».
- **Виджет на главной** — если дополнение объявило `widget`.
- **Кнопка в нижней панели** — для экрана с `nav=1`, если пользователь разрешил её в «Дополнениях»;
  не больше двух кнопок дополнений, они встают перед «Настройками», места панели делятся поровну.
- Дополнения не смешиваются с «Приложениями».

## 7. Данные VestaHome и команды

Подписка (VestaHome шлёт при изменении, не чаще раза в секунду):
```
→ subscribe  what=gps,car,media,night,keys,bt
← gps    fix=1  lat=53.2001  lon=50.1500  speed=42  course=270
← car    speed=42  fuel=31  temp_out=12  …                 (то, что есть: CAN, OBD — имена как в виджете «Автомобиль»)
← media  src=radio  title=Relax FM  text=103,7 МГц  playing=1
← night  value=1
← bt     unit=AA:BB:CC:DD:EE:FF  phone=A4:E2:87:98:D6:9F  hf=2   (адрес Bluetooth ГУ, телефон по Bluetooth, HFP: 2 — подключён, -1 — нет proxy; при изменении)
← key    code=18  st=0  kind=2                        (только keys: кнопка панели или руля, пока впереди окно дополнения или собственное окно его экрана)
← theme  accent=72C059                                (всем, без подписки: тема VestaHome сменилась)
```
`key` — сообщение MCU как есть: `code` — кнопка (18 = 0x12 «вверх / ответить», 20 = 0x14 «вниз / положить трубку»,
7 — экран, 8/9 — дальше/назад; остальные — по журналу VestaHome), `st` 0 нажата / 1 отпущена, `kind` 1 коротко /
2 долго / 3 повтор. Дополнение, которое взяло кнопку себе, **возвращает 2** из обработки `WM_COPYDATA`; любой другой
ответ — VestaHome делает своё (переключает трек, отвечает на звонок…). Брать стоит только то, что не нужно
медиа и телефону, — например, удержание.
Акцент и подсветки дополнения берёт из темы VestaHome: `accent` в `welcome`, затем `theme` при смене.
Команды:
```
→ notify  text=Ворота открываются  ms=3000             (всплывающая строка)
→ open    screen=main                                  (открыть свой экран)
→ media   cmd=toggle|next|prev                         (play / pause — то же, что toggle)
→ volume  value=+1|-1                                  (пока не сделано)
```
`car` — показания с данными, ключ — номер показания: 0 скорость CAN, 1 угол руля, 2 пробег поездки, 3 в движении,
4 средняя, 5 макс., 6 обороты, 7 ОЖ, 8 напряжение, 9 скорость OBD, 10 плата ГУ, 11 усилитель, 12 экран, далее —
как в «Автомобиль → все показания» (значения — с единицами, как там).

### 7.1. Манёвр в верхней строке
Навигатор сообщает следующий манёвр, а VestaHome показывает его «таблеткой» в верхней строке на любом экране; пока
на экране виджет-картинка этого дополнения, таблетка скрыта.
```
→ nav      on=1  turn=90  dist=350 м  street=ул. Льва Толстого  eta=14:41     (только при изменении)
→ nav      on=0                                                               (маршрута нет)
← nav.tap                                                                     (касание таблетки: пора на передний план)
```
`turn` — градусы от -180 до 180 (плюс — направо), 997 — промежуточная точка, 998 — круговое движение, 999 — финиш.
Разбор, сборка команды и значок — `VestaCore/vnav`.

### 7.2. Голосовая подсказка поверх радио
```
→ voice    on=1          (подсказка начинается: VestaHome приглушает радио и пропускает звук ГУ)
→ voice    on=0          (подсказка кончилась: радио обратно)
```
Как у внешнего навигатора штатной оболочки (`0x101D` окну `RadioCommWindow`): есть окно оболочки — дополнение шлёт
`0x101D` ему само; нет — `voice` VestaHome, тот говорит MCU напрямую. Звук — через ~1 с после `on=1` (MCU успевает
убавить радио), `on=0` — через ~0,8 с после конца. Дополнение отключилось посреди подсказки — радио возвращается.

### 7.3. Своя музыка дополнения
```
→ sound    on=1          (дополнение начинает играть свою музыку через waveOut)
```
VestaHome ставит свои плееры (музыка, радио из сети, видео) на паузу и переключает MCU на «медиа», как для своего
плеера; без этого звук waveOut не слышен под радио или Bluetooth. Конца нет: источник остаётся «медиа», пока его не
сменят. Так играет звук Android Auto (VestaAuto).
```
← sound.lost  src=0        (api 2: MCU ушёл с «медиа» на другой источник — MODE, радио, Bluetooth)
```
Один раз после `sound`, пока дополнение снова не скажет `sound`: его музыку больше не слышно — пора остановить
её (VestaAuto говорит телефону «фокус звука потерян», телефон ставит музыку на паузу). `src` — источник MCU.
```
→ playing  state=play  title=Песня  artist=Исполнитель  album=Альбом  app=YouTube Music  pos=42  len=180  art=\Temp\x.jpg
← media.key  key=prev|toggle|next
```
Что играет музыка дополнения. Пока звучит его звук (`sound`), виджеты «Сейчас играет» показывают трек, приложение,
время и обложку. `state` — `play`, `pause` или `stop`; `pos` и `len` — секунды, `pos` VestaHome дальше считает сам,
пока `play`. `art` — картинка обложки (JPEG или PNG) в `\Temp` (это оперативная память): новая обложка — новое имя
файла. Кнопки виджета приходят дополнению как `media.key`, касание виджета открывает экран дополнения.

### 7.4. Навигация у дополнения
```
→ navi  on=1          (дополнение взяло навигацию: идёт сеанс Android Auto)
→ navi  on=0          (отдало)
```
Пока навигация у дополнения, запуски OSMapsCE из VestaHome — плитка в «Приложениях», виджеты «Навигация» и «Карта OSM», маршрут к избранному — открывают экран дополнения: два навигатора сразу делят память и процессор ГУ.

## 8. Чужие программы на картинке

В Windows CE нет компоновщика окон: окно, закрытое VestaHome или свёрнутое, не рисуется, и снять с него картинку
нельзя. Поэтому живая картинка в виджете — только от программы, которая рисует её сама (как OSMapsCE ниже).
Для любой другой навигации VestaHome может показать **последний кадр**: снимок экрана в момент, когда из неё
возвращаются в VestaHome (кнопкой «домой», из «Приложений»), с подписью «снято в 12:40» (настройка в виджете
«Навигация»).

## 9. Ограничения

Нет: своих картинок в описанных экранах (только значки Lucide из скина по имени `icon=`; картинка — только в
виджете, 4.1), звука от дополнения поверх музыки (ввод текста — с версии 2, `type=text`). Добавятся в следующих версиях с
повышением `api`.

## 10. Примеры

- `VestaCore/plugins/sample` — открытый пример на C++ (ПК и CE): кнопка, переключатель, счётчик, виджет и
  экран с кнопкой в нижней панели. С ПК-сборкой VestaHome работает так же, как на ГУ.
- **OSMapsCE как дополнение** (бесплатное, в самой OSMapsCE): виджет «Карта» 2×1 или 2×2 — живая карта вокруг
  машины (плитки из её кэша, по курсу или на север, пробки — как в OSMapsCE), рисуется в фоне, пока OSMapsCE
  запущена и свёрнута; касание — OSMapsCE на весь экран.
